# Editing your website

For your homepage blurb, open **[Edit homepage text](https://github.com/Robsution/robsution.github.io/edit/main/content/home.md)**. That file contains only the two paragraphs. Replace them with your own words, leave a blank line between paragraphs, and save with **Commit changes**. Commit to `main` to publish.

GitHub then builds and updates the site automatically. You do not need to run the workflow manually. Check [Publish website in Actions](https://github.com/Robsution/robsution.github.io/actions/workflows/pages.yml) for completion, then refresh [your website](https://robsution.github.io/). GitHub's Markdown preview shows the text; the published site supplies the typography and layout.

## A few Markdown basics

Write paragraphs normally, with a blank line between them. Optional formatting:

```md
This has *italic text* and **bold text**.

Here is a [link to a paper](https://example.org/paper).

- One item
- Another item

Inline math: $E = mc^2$.

$$
Z = \sum_i e^{-\beta E_i}
$$
```

LaTeX works in the homepage blurb, other page descriptions, and writings. The site renders equations automatically. Math in page titles and metadata is plain text. A LaTeX error stops publication and appears in the workflow's build log; the previously published version remains available.

Links to other pages use their published filename, for example `[Research](research.html)`, not the Markdown filename. For an image, add it to `public/`, then use `![A description of the image](assets/your-image.jpg)`. Keep these paths relative, without a starting `/`.

## Sections, dates, and entries

Research, teaching, and making files begin with a small title block:

```md
---
title: Research
description: A short line under the page title.
---
```

Change the words after the colons. Keep the two `---` lines. These are simple `key: value` lines: do not add quotation marks or split one value over multiple lines.

Below that, `##` begins a numbered section. The site adds the numbers for you. An entry uses `### DATE | Title`; the text before `|` becomes its small left-hand label. You can copy an existing entry, change it, move it, or remove it:

```md
## Teaching

### 2026–2027 | Course title

What you did and where you taught.

[Course resources](https://example.org/course)
```

Use `### A heading` without a `|` for a normal subheading, `#### A small label` for a small heading, and `> A short aside` for a quieter note. A `---` after the entries ends the entry list, allowing a general footnote below it. Headings inside code fences are left as code.

On the homepage, keep the single `## Currently` section in `content/currently.md` and use labels such as `RESEARCH` or `TEACHING` instead of dates. In `content/writings.md`, keep two `##` sections: informal writing first, academic writing second. You can rename both headings and rewrite their introductions. Actual pieces come from the individual files below.

## Add a writing

In [content/writing/](https://github.com/Robsution/robsution.github.io/tree/main/content/writing), choose **Add file → Create new file**. Give it a lowercase filename with hyphens and `.md`, such as `a-question-about-ecology.md`. Paste this starting point and replace the example text:

```md
---
title: Your title
date: 2026-10-11
section: posts
description: One sentence for the list of writings.
---

Start writing here.

## A section heading

More text, links, or equations.
```

Use `section: posts` for informal writing, or `section: academic` for research writing and expositions. The date must be `YYYY-MM-DD`. An optional `kind:` line replaces the date label in the list with a label of your choosing. Within each group, newest pieces appear first. The homepage automatically links to your three newest informal posts.

The filename becomes the address: `a-question-about-ecology.md` becomes `a-question-about-ecology.html`. Avoid renaming a published file if people may already link to it. The names `index`, `research`, `writing`, `teaching`, and `making` are reserved for the main pages.

To turn the current sample into your own piece, edit [the sample](https://github.com/Robsution/robsution.github.io/edit/main/content/writing/typesetting-a-thought.md), replace its title, description, date, and body, remove `kind: Layout specimen`, and remove `sample: true` (or set it to `false`). Sample entries are labeled and kept off the homepage's recent-post list. You can also delete the sample file; no template or test changes are needed. Keep the empty `.gitkeep` file if the folder has no writings left.

## Update the CV, portrait, or personal details

Upload a new PDF to `public/`, then change `cvFile` and `cvDate` in `content/site.json`. For example:

```json
"cvFile": "cv-2026-10.pdf",
"cvDate": "October 2026"
```

Both CV download links and their dates update together. For your photo, upload an image to `public/` and update `portrait` and `portraitAlt`. Replacing the existing `portrait.jpg` also works. Public files are downloadable by visitors.

In the same settings file, `shortName` is the masthead name; `givenNames` and `familyName` form the large homepage heading; `name` is the full name used in page titles and the footer. `role`, `affiliation`, `location`, and `email` control the other personal details. Preserve the JSON quotation marks and commas. Leave the appearance settings as they are to keep your chosen design.

## If you edit on your computer

First run `git pull --ff-only` in this site's folder to bring in any edits you made on GitHub. Edit the same content files in your preferred text editor, run `npm run build`, and refresh the local preview. The preview does not rebuild automatically. Then commit and push your changes to `main` to publish. See the [README](README.md) for preview setup.

If publication fails, open the failed step in [Actions](https://github.com/Robsution/robsution.github.io/actions/workflows/pages.yml). Typical causes are a missing comma in `site.json`, an invalid date, a broken local link, or a LaTeX typo. Fix the file and commit again; publication retries automatically. Content changes do not require changes to the tests.
